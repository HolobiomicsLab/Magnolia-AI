Symptoms: `generate_restraints` tool failed with error "actpass file must have exactly 2 lines" for all 5 recently-prepared docking runs (KFERQpK, KFERQpF, KFERQpQ, KFERQpA_C, ApKFERQ_N) in `p2rank1_s5000` directories. Each had receptor.actpass and ligand.actpass files with multiple residue lines rather than the expected 2-line format.

Cause: The HADDOCK3 workflow for these runs was configured with multi-residue active/passive definitions (likely from P2Rank pocket 1), but `generate_restraints` expects exactly 2 lines per actpass file: line 1 = active residues, line 2 = passive residues. The multi-residue format broke the parser.

Fix: Either regenerate the actpass files with the correct 2-line format (active residues on line 1, passive on line 2, space-separated) before calling `generate_restraints`, or manually construct the HADDOCK3 restraints file (tbl format) using the residue lists directly, bypassing `generate_restraints`. The stage_gate 'docking_inputs_ready' already passed (config/receptor/ligand/restraints exist), so the restraint files may have been pre-generated by the workflow setup; the bottleneck is the `generate_restraints` utility itself.

Red herrings eliminated: The error is NOT about missing actpass files, NOT about format of the config/PDB files, and NOT about HADDOCK3 runtime issues — all stage_gate checks passed. The utility `generate_restraints` is simply not designed for multi-residue actpass files.
