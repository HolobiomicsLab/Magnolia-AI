# Harness-neutral Magnolia — Plan 3: executors, usage governor and routing

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Magnolia's non-interactive campaign workers/reviewers, daemon helpers and router evaluator use the member's own client login. Every subscription invocation is governed; a client runs a role only with the role's proved capabilities.

**Architecture:**
- **Common contracts first.** One route resolver, typed outcome/limit, per-invocation usage record, complete launch context and role-policy delivery contract.
- **Governor and state.** Cross-process admission, durable quota waits and phase-aware campaign continuation; each physical invocation, including repairs/resumes, has its own reservation and receipt.
- **Executors.** `campaign_runner/executors/` selects by client prefix. Preserve `WorkerExecutor.run(...)` and existing result fields, adding outcome/session metadata compatibly. Retain distinct OpenCode campaign, helper and evaluator recipes.
- **Role limits.** Neutral roles produce byte-identical OpenCode campaign files and required policies for new clients. Native enforcement follows accepted capability evidence.
- **Callers and routing.** Campaigns, helpers and client evaluators share contracts; all five role consumers use the same resolver. `magnolia usage` reports resolved routes, usage and live waits.

## Decisions for LFX before execution

- **D1. Accounting and governor defaults.** One run means one physical client invocation, including every resume, empty-output retry, reviewer format repair and helper recovery. Reserve daily capacity before launch, including in-flight work; record actual invocations once. The effective cap is `min(role configured cap, governor cap)`: worker/reviewer caps come from their configs (not `Stage.max_steps`); helper default 40, evaluator one turn. OpenCode campaign caps must reach the dedicated service at startup/reconfiguration; helper/evaluator keep their own recipe with a proved cap. Claude/Vibe use their proved turn limits; Codex needs a proved native or supervising bound, never an invented flag. Refuse an unsupported bounded configuration. Proposal per subscription: `max_concurrent=1`, `max_runs_per_day=20`, `max_turns_per_run=40`, `min_seconds_between_runs=60`. These are conservative proposals, not measured account capacity. LFX confirms or replaces the four numbers; offline tests can use explicit fixture policies meanwhile.
- **D2. Codex campaign roles.** Refuse **both worker and reviewer** unless Task 0 proves usable permitted reads, denied secret reads, no shell and confined edits through normal persisted trust; reviewer permits no edits. A read-only sandbox or moving cwd into `work/` is insufficient. **Only if the gate fails**, ask LFX: accept a documented reduced-guarantee exception, with an amendment to design 8.1, or keep refusal (**default**). An exception cannot pass unchanged-role acceptance. Codex remains a helper/evaluator route under their separate contracts; no unsupported claim that shell is its only read mechanism.
- **D3. Vibe memory-server API key.** The observed stdio environment is **minimal without provider keys**, not absent. Proposal: project-bound loopback HTTP memory service, API key only in the server environment, URL in Vibe config (Task 9). Alternatives: server-side keychain lookup or a private API-key file. These are API billing credentials, never client subscription credentials. A file would require explicit role read denial; mode 0600 alone does not isolate same-user agents. LFX chooses; a non-HTTP choice requires a replacement packet with equivalent binding/privacy tests before implementation. Vibe-memory acceptance waits for this decision and implementation.
- **D4. Vibe worker edits.** Design 8.1 disables write/edit, contradicting the worker's required `work/**` edits. Proposal/default resolution: amend 8.1 to permit **guarded worker edits only after Task 0 proves strict pre-tool denial outside its own work tree and B3's fail-closed paths**. Until LFX accepts that amendment and the gate passes, refuse the Vibe worker. A failed gate also means refusal; reviewer, helper and evaluator remain available under their own contracts.

Rulings carried forward:
- **R1. Trust.** Never pass `--trust` or grant trust automatically. Vibe's read-only precheck follows canonical paths, the nearest trusted/untrusted ancestor and enabled project configuration sources, then verifies the required hook identity. Do not instantiate a trust-store manager that may write. Codex project trust and hook review must likewise be persisted normally.
- **R2. Retries.** Quota overrides every retry layer. No immediate/pre-reset retry; known reset permits later governed continuation, unknown reset requires an explicit command. Ordinary OpenCode worker behavior stays `max_format_retries=2` (up to three invocations); reviewer disables executor empty retries and retains its configured format-repair loop. Helper continuation/stale-session behavior remains distinct. New clients get one same-session empty-output retry at most, only on ordinary successful-but-empty output.
- **R3. Memory/critic billing.** Existing API-billed memory and critic routes remain outside subscription admission; preserve round 6c's sticky session identity and quality-floor behavior after accepted integration.

## Global Constraints

- **Paths:** campaign/router/launcher/agent/test paths below are relative to `opencode_cc_mem/`. `src/compchem_memory/` and memory tests are relative to `opencode_cc_mem/mcp-servers/compchem-memory/`. `docs/harness-adaptation.md` is at the **repository root**; other harness plan/probe/acceptance docs are under `opencode_cc_mem/docs/`.
- **OpenCode preservation.** Preserve worker/reviewer retries, dedicated service, parser/result/error behavior, reviewer DB fallback, daemon recipe/session behavior and evaluator standalone/private-server DB/plain-stdout behavior. Preserve campaign agent Markdown bytes. The **only approved governor effects** are **admission/daily-limit waits, governor caps and quota-stop behavior**. Do not silently add campaign `--agent`/`--auto` flags to helper/evaluator calls. Legacy helper/evaluator tool semantics stay characterized; new-client role restrictions are explicit, not retrofitted to OpenCode.
- **Credentials/flags.** No alternate `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `VIBE_HOME`; no client `CODEX_API_KEY`/`ANTHROPIC_API_KEY`; no `claude --bare`, permission bypass, hook-trust bypass or `--trust`. Never read/copy subscription auth files or keychain entries. Vibe `--auto-approve` is noninteractive-only and requires the proved disabled-tool/strict-hook contract. Test the effective child environment, not just renderer additions. `JevEvaluator._api_key()` is exempt and unchanged; record the A1 conflict locally for Tao, without sending a message.
- **Required enforcement.** A required role policy/config is immutable for that invocation and outside its editable tree. Missing/invalid/stale/untrusted enforcement, unknown tool/input or unresolved targets deny/refuse **all affected operations, including reads**, before useful work. Optional interactive policy keeps its legacy behavior separately. No native/MCP shell, member tool, code-mode call or delegation may bypass a campaign role.
- **Private state.** Policy: `$XDG_CONFIG_HOME/magnolia/usage-policy.yaml` (fallback `~/.config`); ledger: `$XDG_STATE_HOME/magnolia/usage-ledger.jsonl` (fallback `~/.local/state`); lock/admission/wait state beside the ledger. No prompts, replies, environment values or keys in usage state. Project identity is a digest.
- **Interactive and API boundaries.** Interactive sessions never acquire governor slots. Memory/critic API calls do not acquire them either. No automatic fan-out or unbounded background recovery.
- **Live work:** separate LFX execution-time authorization, disposable demo projects, at most ten short physical invocations per client **across Task 0 and acceptance, including retries**. Count ancillary memory/critic calls separately against their explicit allowance. Vibe uses `VIBE_DISABLE_TELEMETRY=true`. No real secret reads; plant synthetic sentinels.
- **Implementation verification:** each task writes named failing tests, runs its listed command to observe the relevant failure, implements, reruns to pass, then commits only its named files. Record counts and source revision. Commands are from the indicated package directory; use stub clients/fake clocks and no network by default. Existing tests may change only in the files named by the task. Full suites run at phase boundaries, not after every small edit. Bash launcher remains Bash 3.2-compatible.

## Review Focus

1. **Complete role enforcement:** permitted reads/work edits succeed; secret/recursive/alias reads, outside edits, shells, indirect tools and delegation are denied through actual native hook responses, including failure paths (Tasks 0, 2, 6–8).
2. **One physical invocation, one admission/receipt:** campaign and helper races never exceed concurrency/daily reservations; crashes do not reclaim work still alive; usage on resumed sessions is a delta (Tasks 1, 3, 5, 10–12).
3. **Quota crosses every layer:** empty/partial output and either exit code cannot trigger empty, JSON, campaign or stale-session repair. Shared cooldown prevents another caller from launching (Tasks 3–4, 6–12).
4. **Durable continuation:** quota before launch consumes no repair attempt; reviewer quota resumes validation without rerunning the worker; known reset wakes before the stop-set exit, unknown reset stays held (Tasks 4, 10).
5. **Compatibility and real consumers:** OpenCode recipes remain characterized, all five routes resolve identically in launch/report, `agent` executes, and mixed-client campaigns yield usable traces/distillation (Tasks 5, 10–15).

### Task 3: Governor, cooldowns and per-invocation accounting

**Files:** Create `campaign_runner/governor.py`; extend invocation plumbing in `campaign_runner/{process,workers}.py`; tests `tests/{test_governor,test_campaign_process}.py`.

**Interfaces/invariants:**
- `Policy.load(path=None)`: missing default policy uses D1 defaults; a supplied unreadable/invalid policy **refuses**, never silently weakens a stricter budget. Validate positive limits and optional `max_price_per_run`; `api_key_providers` is an explicit list.
- `Governor.admit(request, control) -> Admission | QuotaWaiting`, where request carries route/run identity/cap. Admission is an exception-safe context manager with idempotent finalization, `effective_cap`, actual-work identity and usage completion. Own admission at the **physical invocation boundary**, not once around `WorkerExecutor.run`; every hidden resume/repair must re-enter it.
- Subscription keys: `claude-code`, `codex`, `vibe`, `opencode:<provider>`. Same OpenCode provider shares a budget across models. Declared API providers are recorded without subscription waits/caps; unknown providers default to subscription. Never inspect credentials to classify.
- Atomic reservations include in-flight work at the last daily slot. Day is UTC calendar day; week report is the selected day plus six preceding UTC days. Spacing is between starts. Cancel a reservation only if launch demonstrably never occurred; spawned failures/timeouts/crashes count, with unknown usage as needed.
- Cross-process file locking protects short state transitions only. No sleeping/process I/O under global or campaign locks; waits check cancellation/pause/stop. Durable waiting records identify caller/key/reason/reset independently of completed ledger rows.
- Quota completion persists a shared key cooldown before any next admission. Known reset may clear when due; unknown reset has no timer. Explicit resume clears that observed hold, not daily budgets. Provide `resume_key(key)` for operator commands and `report(day)` for day/week/wait reporting.
- Keep one durable completion per invocation even after exceptions/recovery. PID death/lease expiry alone cannot free a slot: verify actual child/process group **and service-side request** have ended, otherwise retain/reconcile the hold. Track enough identity to avoid PID reuse. Ledger append/finalization recovery must not duplicate accounting.
- Stream observation/termination in `run_process` must deliver a typed quota/cap/cancel outcome before callers can retry, retaining partial output/usage. A client that hides required mid-run signals is a measured limitation; do not claim immediate stop without an observed mechanism.
